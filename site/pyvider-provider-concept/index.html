    Pyvider provider concept

    Of course. Solidifying the resource lifecycle contract is a critical step to ensure the framework is robust and produces predictable behavior for end-users. It's about making sure that what Terraform plans to do is exactly what the provider actually does.

    Let's break down what's involved into three key areas: Documentation, Framework-Level Hardening, and a Rigorous Testing Strategy.

    Core Concept: The Plan/Apply Contract¶

    The fundamental promise of Terraform is predictability. A user runs terraform plan to see a blueprint of changes, and terraform apply to execute that exact blueprint. The provider is the bridge that makes this possible.

    The contract is simple but strict:

    1. plan() is a Promise: The plan method receives the prior state and the new configuration. It must return a complete and accurate representation of the resource's state as it will exist after apply is finished. This is the "planned state."
    2. apply() is the Fulfillment: The apply method receives the exact planned_state object from the plan step. It performs the real-world actions (creating APIs, writing files, etc.).
    3. The Golden Rule: The state object that apply returns must be identical to the planned_state it received.

    If plan promises an ID of "abc" but apply returns a state with an ID of "xyz", the contract is broken. Terraform will detect this discrepancy and show a perpetual diff, forcing a new plan and apply on every run, which is a critical provider bug.

    Actionable Steps to Solidify the Contract¶

    Here is a detailed breakdown of the work involved.

    1. Documentation for Component Developers¶

    You cannot enforce a contract that developers don't know about. The first step is to create clear, explicit documentation.

    • Create DEVELOPING_RESOURCES.md: This guide should be the canonical source of truth for anyone building a resource with pyvider.
    • Clearly Define Responsibilities:
      • plan() Method: Document that this method's primary job is to return a fully populated instance of the resource's state_class. Explain that all computed=True attributes must be given a value in the plan.
        • For Creates: If a value is generated based on configuration (e.g., a resource ID is a hash of its name), the plan method should perform that generation. If a value is generated by an external API and truly unknowable at plan time, this requires handling "unknown values," which is a more advanced topic. For now, the focus should be on predictable computed values.
        • For Updates: The plan must show the final state after the update. If a configuration change from "v1" to "v2" will cause a computed last_updated timestamp to change, the plan must reflect that change, even if the exact timestamp is unknown.
      • apply() Method: Document that the simplest and most robust way to fulfill the contract is to return the planned_state object directly after performing the necessary side effects. The apply method's job is to make the real world match the plan, not to re-calculate the state.

    2. Framework-Level Hardening¶

    The framework itself can be enhanced to help developers detect and prevent contract violations.

    • Implement a Post-Apply Check: The ApplyResourceChangeHandler is in a unique position. It receives the planned_state in its request and gets the final_state back from the resource's apply method.
      • Action: After the await resource_handler.apply(ctx) call, the handler should perform a comparison: assert final_state == planned_state.
      • Behavior: If the assertion fails, the framework should log a severe, detailed error message pinpointing the discrepancy. This immediately alerts the developer to a contract violation within their resource logic, rather than letting it silently fail in Terraform.

    3. A Rigorous Testing Strategy¶

    This is the most critical part. You must have an automated way to verify the contract for every resource.

    • Create a Lifecycle Test Harness: Develop a standard test pattern that every resource must pass. This test simulates the create, update, and delete lifecycle from the framework's perspective.
    • The "Create" Lifecycle Test:
      1. Instantiate the resource.
      2. Define a valid configuration for creating the resource.
      3. Call resource.plan() with the config. This yields the planned_state.
      4. Assert that the planned_state contains valid, non-null values for all computed attributes.
      5. Call resource.apply() with the planned_state. This yields the final_state.
      6. Assert final_state == planned_state. This is the most important check.
      7. Call resource.read() using the final_state to verify that the real-world state matches.
    • The "Update" Lifecycle Test:
      1. Start with a pre-existing prior_state.
      2. Define a new config that represents an update.
      3. Call plan() with the prior_state and new config to get the planned_state_for_update.
      4. Call apply() with the planned_state_for_update.
      5. Assert the returned final_state is identical to planned_state_for_update.
    • Expand the Test Suite: Apply this lifecycle test pattern to every resource. Start with file_content and then create new, more complex test resources to cover different scenarios (e.g., resources with nested objects, lists of objects, and more complex computed values).

    Example: Implementing and Testing a local_directory Resource¶

    To make this concrete, here is how you would implement and test a new local_directory resource, focusing on fulfilling the contract.

    I will generate a bash script to create the necessary files.

    #!/bin/bash
# 🛠️ Project Patching Script
set -eo pipefail

# --- Logging ---
log_info() { echo -e "ℹ️  $1"; }
log_patch() { echo -e "🩹 $1"; }
log_success() { echo -e "✅ $1"; }

# --- Operations ---
log_info "Applying file changes for local_directory resource..."
mkdir -p pyvider/src/pyvider/components/resources/
mkdir -p pyvider/tests/resources/

# --- 1. Define the Resource Implementation ---
log_patch "Creating: pyvider/src/pyvider/components/resources/local_directory.py"
cat <<'EOF' > pyvider/src/pyvider/components/resources/local_directory.py
import os
import stat
from pathlib import Path
from typing import cast

import attrs

from pyvider.exceptions import ResourceError
from pyvider.hub import register_resource
from pyvider.resources.base import BaseResource
from pyvider.resources.context import ResourceContext
from pyvider.schema import PvsSchema, a_num, a_str, s_resource
from provide.foundation import logger
from pyvider.common_types import StateType

@attrs.define(frozen=True)
class LocalDirectoryConfig:
    """Configuration for the local_directory resource."""
    path: str
    permissions: str | None = "0755"

@attrs.define(frozen=True)
class LocalDirectoryState:
    """State for the local_directory resource."""
    path: str
    permissions: str
    # Computed attributes
    id: str
    file_count: int

@register_resource("pyvider_local_directory")
class LocalDirectoryResource(BaseResource["pyvider_local_directory", LocalDirectoryState, LocalDirectoryConfig]):

    config_class = LocalDirectoryConfig
    state_class = LocalDirectoryState

    @classmethod
    def get_schema(cls) -> PvsSchema:
        return s_resource({
            "path": a_str(required=True, description="The path of the directory to manage."),
            "permissions": a_str(optional=True, description="The permissions for the directory in octal format."),
            "id": a_str(computed=True, description="The absolute path of the directory."),
            "file_count": a_num(computed=True, description="The number of files in the directory."),
        })

    async def read(self, ctx: ResourceContext) -> LocalDirectoryState | None:
        if not ctx.state or not ctx.state.path:
            return None

        path = Path(ctx.state.path)
        if not path.is_dir():
            return None

        current_permissions = oct(path.stat().st_mode & 0o777)
        file_count = len([f for f in path.iterdir() if f.is_file()])

        return self.state_class(
            path=str(path),
            permissions=current_permissions,
            id=str(path.resolve()),
            file_count=file_count
        )

    async def plan(self, ctx: ResourceContext) -> tuple[StateType | None, bytes]:
        config = cast(LocalDirectoryConfig, ctx.config)
        if not config:
            return None, b"" # Should not happen if config is required

        # --- Fulfilling the Plan/Apply Contract ---
        # The plan MUST predict all computed values.

        # 1. Predict the 'id'. This is knowable from the configuration.
        predicted_id = str(Path(config.path).resolve())

        # 2. Predict the 'file_count'.
        #    - If we are creating the directory (no prior state), the count will be 0.
        #    - If we are updating, we assume the file count doesn't change unless
        #      the resource's purpose is to manage files inside it. For this
        #      example, we'll keep the existing count on update.
        predicted_file_count = 0
        if ctx.state and isinstance(ctx.state, self.state_class):
            predicted_file_count = ctx.state.file_count

        # 3. Construct the complete planned state.
        planned_state = self.state_class(
            path=config.path,
            permissions=config.permissions or "0755",
            id=predicted_id,
            file_count=predicted_file_count
        )

        return planned_state, b""

    async def apply(self, ctx: ResourceContext) -> tuple[StateType | None, bytes]:
        # If planned_state is None, it's a delete operation.
        if not ctx.planned_state:
            await self.delete(ctx)
            return None, b""

        planned_state = cast(LocalDirectoryState, ctx.planned_state)
        path = Path(planned_state.path)

        # Perform the real-world action.
        path.mkdir(parents=True, exist_ok=True)

        try:
            permissions_octal = int(planned_state.permissions, 8)
            path.chmod(permissions_octal)
        except (ValueError, TypeError) as e:
            raise ResourceError(f"Invalid permissions format: {planned_state.permissions}. Must be an octal string like '0755'.") from e

        # --- Fulfilling the Plan/Apply Contract ---
        # The state returned by apply MUST be identical to the planned state.
        # The easiest way to guarantee this is to return the planned state directly.
        return planned_state, b""

    async def delete(self, ctx: ResourceContext) -> None:
        state = cast(LocalDirectoryState, ctx.state)
        if not state or not state.path:
            return

        path = Path(state.path)
        if path.is_dir():
            try:
                # For safety, only remove if empty. A real provider might have a 'force_destroy' flag.
                if not any(path.iterdir()):
                    path.rmdir()
                else:
                    logger.warning(f"Directory {path} is not empty, not removing.")
            except OSError as e:
                logger.error(f"Failed to remove directory {path}: {e}")

EOF

cat <<'EOF' > pyvider/tests/resources/test_local_directory_lifecycle.py
import pytest
import asyncio
from pathlib import Path
import shutil

from pyvider.components.resources.local_directory import LocalDirectoryResource, LocalDirectoryConfig, LocalDirectoryState
from pyvider.resources.context import ResourceContext

@pytest.fixture
def temp_dir() -> Path:
    """Provides a temporary directory path for testing."""
    path = Path("/tmp/pyvider_test_dir")
    if path.exists():
        shutil.rmtree(path)
    yield path
    if path.exists():
        shutil.rmtree(path)

@pytest.fixture
def resource() -> LocalDirectoryResource:
    """Provides an instance of the resource."""
    return LocalDirectoryResource()

@pytest.mark.asyncio
async def test_create_lifecycle_contract(resource: LocalDirectoryResource, temp_dir: Path):
    """
    Tests the full create lifecycle, explicitly checking the plan/apply contract.
    """
    # 1. Define the configuration for a new resource.
    config = LocalDirectoryConfig(path=str(temp_dir), permissions="0775")
    create_context = ResourceContext(config=config, state=None)

    # 2. Get the plan.
    planned_state, _ = await resource.plan(create_context)

    # 3. Assert the plan is complete and correct.
    assert isinstance(planned_state, LocalDirectoryState)
    assert planned_state.path == str(temp_dir)
    assert planned_state.permissions == "0775"
    assert planned_state.id == str(temp_dir.resolve()) # Computed 'id' is predicted.
    assert planned_state.file_count == 0 # Computed 'file_count' is predicted for a new dir.

    # 4. Apply the plan.
    apply_context = ResourceContext(config=config, planned_state=planned_state)
    final_state, _ = await resource.apply(apply_context)

    # 5. *** THE GOLDEN RULE ASSERTION ***
    # The state returned by apply must be identical to the one from plan.
    assert final_state == planned_state, "The state returned by apply() did not match the planned_state."

    # 6. Verify the real world.
    assert temp_dir.exists()
    assert temp_dir.is_dir()
    assert oct(temp_dir.stat().st_mode & 0o777) == "0o775"

    # 7. Verify the read operation.
    read_context = ResourceContext(config=None, state=final_state)
    read_state = await resource.read(read_context)
    assert read_state is not None
    assert read_state.path == str(temp_dir)
    assert read_state.permissions == "0o775" # read() gets the canonical form
    assert read_state.file_count == 0

EOF
